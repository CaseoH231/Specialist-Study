# Specialist Study — notes for Claude

Photos of the user's Specialist Maths work, sorted into topics automatically, with notes underneath (plain HTML/CSS/JS ES modules, no build step). Personal project, Cloudflare Worker `specialist-study`. Sister app of `CaseoH231/bio-study` and `CaseoH231/Methods-study`.

- **"Do the weekly notes"** (or a scheduled Sunday run): follow `docs/WEEKLY.md`.
- The owner's library is `data/library.json` + `photos/<id>.jpg` on `main` in this repo. The app saves to it through the Worker (`/api/upload`, `/api/change`) with the GITHUB_TOKEN secret; changes are small ops (`lib.js` `applyOps`) applied to the newest copy, so the app and the weekly job never overwrite each other. Writes always need APP_PASSCODE.
- Sorting (`worker/sort.js`) and the helper (`worker/assistant.js`) use free Workers AI (Gemma 4, `env.AI`, thinking off) and are locked to OWNER_IPS / APP_PASSCODE (`worker/access.js`). The helper only suggests; the app applies after "Do it". Sorting only picks a topic and title – it doesn't transcribe.
- Friends see the owner's library read-only; their own photos stay on their device (IndexedDB + localStorage `specialist-study-mine-v1`, ids start with `my-`).
- Course page (`#/course`, `course.js` + `worker/course.js`, the same files in bio-study, Specialist-Study and Methods-study – keep them identical): the owner uploads the study design and work plan (PDF/images) to `course/` in the repo via `/api/course` (APP_PASSCODE); everyone views them at `/course/<file>`.
- Study tools (v2 design, the same as Methods Study but teal + coral and Specialist content; no graph plotter – the user didn't want one): `practice.js` (Specialist question generators – every answer is re-checked independently from the question's own numbers in `tests/test_tools.cjs`; add a matching check when adding a generator), `formulas.js` (Specialist formula sheet), planner (in `app.js`; shared dates are `events` in library.json via `add_event`/`delete_event` ops, friends' own dates are local `my-e…`), topic confidence ratings (local), share / print. Routes `#/practice`, `#/formulas`, `#/planner`, `#/course`. The app code (`app.js`, `lib.js`, `unlock.js`, the page parts of `practice.js`/`formulas.js`) matches `CaseoH231/Methods-study` apart from names and content – keep fixes in step.
- **Uploads only – the user's rule:** a study helper, not "AI help". Practice questions only cover things that match the uploaded work (topic names + photo titles), via `unlock.js` – every generator has `keys` (word starts) that must match. Formulas are stricter: only ones **explicitly written on a photo** (photo `formulas: [names]`, tagged by the weekly notes job with `tools/notes.py formulas`) or **unlocked on request** (library `unlocked`, via the helper bot's `unlock_formula` / `lock_formula` actions) are shown – a topic name alone unlocks none. Nothing uploaded → locked. The helper bot only answers from the uploads and their notes; weekly notes stick to what's on the photo. Never add content that bypasses this.
- Run `bash tests/run_tests.sh` before pushing; it must PASS. Tests fake GitHub and the AI (`tests/fakes.cjs`) – never call the real ones.
- Each release: bump `CACHE` in `sw.js` (`specialist-study-vN`) and add any new file to its FILES list.
- Deploy: `python3 tools/build_worker.py OUT && cd OUT && npx wrangler deploy` (packs the files into the Worker script). Data changes (library/photos) need no redeploy.
- Commit and push to `main`. Don't ask for permission to start; just do the work and push.
- After every change, summarise in plain language and end with `Total lines of code: N`, counted with:
  `find . -path ./.git -prune -o -path ./vendor -prune -o -path ./node_modules -prune -o -type f \( -name '*.js' -o -name '*.cjs' -o -name '*.py' -o -name '*.html' -o -name '*.css' -o -name '*.sh' -o -name '*.webmanifest' \) -print | xargs cat | wc -l`
